# Threat model

This is a study fork: see [CLAUDE.md](../CLAUDE.md) for what may and may not be said about it. This
page lists what the vault protects against, how each protection is proven, and what is still open.
It adds no feature.

Each row gives a **threat** (what could go wrong), the **attack** that would exploit it (in prose,
never as a command), the **control** in the code (`file:line` on this branch, or `none`), the
**evidence** (a test name, a check printed by `make demo`, or the lines that describe a limit) and a
**status**:

- `proven`: a test or a demo check fails if the control stops working;
- `not tested`: the control exists in the code, but no test proves it;
- `open`: a known limit, not addressed.

## How to check it yourself

- Unit tests: `cargo test -j 4`.
- End-to-end tests (cited in T2 to T6, T9, T11 to T15, T17, T19, T22, T24, T25, T28, T37), against a real PostgreSQL:
  `VAULT_TEST_DATABASE_URL=postgres://postgres@localhost:5432/postgres VAULT_TEST_REQUIRE_DB=1 cargo test -j 4 --features key_custodian --test vault_e2e`,
  with the URL of a PostgreSQL user allowed to create databases (the one above is the CI's). Without
  these two variables, they are skipped and still reported as passed.
- The re-hash tests without the custodian feature (T28): the same command without
  `--features key_custodian`, filtered on `rehash_`; under the kv feature (T28):
  `--features key_custodian,kv` and the test `rehash_refuses_to_run_with_kv`. No Redis is needed.
- The rotation tests without the custodian feature (T22): the same command without
  `--features key_custodian`, filtered on `rotation_`; under the kv feature (T22):
  `--features key_custodian,kv` and the test `rotation_refuses_to_run_with_kv`; with an external
  key manager (T22, T23): `--features key_custodian,external_key_manager`, the test
  `rotation_with_external_key_manager` and `VAULT_TEST_KEY_MANAGER_URL` set to a running
  Hyperswitch Encryption Service (the CI job below shows how it is built and started).
- The JWE middleware tests (T16): the same command with `--features key_custodian,middleware`,
  filtered on `middleware_` (the other tests send plain JSON and cannot pass under that feature).
- Dependencies (T31 to T33): the CI job "Dependencies", configured in `deny.toml`; the policy tests
  (T31): `cargo test -j 4 --test dependency_policy`.
- Demo checks: `make demo` (last line `DEMO OK`).
- Every reference in this table exists: `scripts/check-threat-model.sh`.

The end-to-end tests and the demo also run on every pull request, in the CI job "End-to-end tests and
demo against PostgreSQL" (with a step for the middleware tests), and the two re-hash modes in "Re-hash without the key_custodian feature"
and "Re-hash refusal with the kv feature", and the three rotation modes in "Master key rotation
without the key_custodian feature", "Master key rotation refusal with the kv feature" and
"Master key rotation with an external key manager". OpenSSF Scorecard runs as a report in the CI job
"Scorecard": its results stay in the run, unpublished. The script above runs in the CI job "Threat
model references". It proves
that each cited test, line and demo check exists, not that it says what the row claims: open the
reference to check that.
