# Audit Log Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Record one metadata-only audit entry per vault operation in a PostgreSQL table, fail-closed.

**Architecture:** A new `src/audit.rs` module holds the entry types, a one-method sink trait
(`AuditInterface`), pure functions that build a `PendingAudit` from each request type, and a `record`
function that writes the entry and returns either the handler's result or an audit error. Each handler
is split into an inner function; the public handler builds the `PendingAudit`, runs the inner function,
then calls `record`. `Storage` implements the sink with a direct diesel insert (no KV path).

**Tech Stack:** Rust, axum 0.7.5, diesel 2.3.12 with async-bb8-diesel 0.3.0, time 0.3, uuid 1.23
(feature `v7` already enabled), tokio (feature `macros` already enabled). No new dependency.

**Spec:** `docs/superpowers/specs/2026-11-20-audit-log-design.md`

## Review Focus

1. A caller sends `x-request-id: 4111111111111111`: the entry's `request_id` must be NULL, not the number. Test in Task 2 (`parse_request_id_rejects_non_uuid`).
2. A fingerprint batch whose labels or data contain a card number: the entry has no label, data, key or fingerprint id. Test in Task 4 (`fingerprint_entry_has_no_payload`).
3. A request that fails validation before any database work (empty `entity_id`, bad TTL) must still produce a `failure` entry with status 400. The `validate()` call sits inside the wrapped inner function. Test in Task 2 (`record_maps_validation_error_to_400`).
4. A retrieve of expired data (TTL passed) returns 404 and must be recorded as `failure` / `NotFoundError`. Covered by Task 2 (`record_writes_failure_entry`), since the TTL branch returns `NotFoundError` from inside the inner function.
5. A merchant, customer or reference id longer than its column (255): the insert must not fail and turn a normal answer into a 500. Ids are truncated to 255 characters in the `PendingAudit` builder. Test in Task 2 (`pending_truncates_long_ids`).

### Task 2: Audit core module

**Covers:** D2, D3, D4, D5

**Files:**
- Create: `src/audit.rs` (types, trait, `record`, tests in `#[cfg(test)] mod tests`)
- Modify: `src/lib.rs` (`pub mod audit;`)

**Interfaces:**
- Consumes: `schema::audit_log` (Task 1); `crate::error::{ApiError, ContainerError, StorageError}`; `crate::utils::date_time::now()`.
- Produces:
  - `pub enum AuditOperation { LockerAdd, LockerRetrieve, LockerDelete, Fingerprint, VaultAdd, VaultRetrieve, VaultDelete, EntityCreate, KeyTransfer, CustodianKey1, CustodianKey2, CustodianDecrypt }` with `pub fn as_str(&self) -> &'static str` returning `locker_add`, `locker_retrieve`, `locker_delete`, `fingerprint`, `vault_add`, `vault_retrieve`, `vault_delete`, `entity_create`, `key_transfer`, `custodian_key1`, `custodian_key2`, `custodian_decrypt`.
  - `pub fn parse_request_id(raw: Option<&str>) -> Option<String>`: `Some` only if `uuid::Uuid::parse_str` succeeds; returns the hyphenated lowercase form.
  - `pub struct PendingAudit` with `pub fn new(tenant_id: &str, request_id: Option<String>, operation: AuditOperation) -> Self`, builder methods `pub fn merchant(self, id: &str) -> Self`, `pub fn customer(self, id: &str) -> Self`, `pub fn resource(self, id: &str) -> Self`, and `pub fn finish<T>(self, result: &Result<T, ContainerError<ApiError>>) -> AuditEntry`.
  - `#[derive(Debug, Clone, serde::Serialize, diesel::Insertable)] #[diesel(table_name = schema::audit_log)] pub struct AuditEntry` with exactly the 11 Task 1 columns as fields (`created_at: time::PrimitiveDateTime`, `status_code: i16`; `audit_id` from `uuid::Uuid::now_v7()`).
  - `pub(crate) trait AuditInterface { async fn insert_audit_entry(&self, entry: AuditEntry) -> Result<(), ContainerError<StorageError>>; }`, the only method (D5).
  - `pub(crate) async fn record<S: AuditInterface, T>(sink: &S, pending: PendingAudit, result: Result<T, ContainerError<ApiError>>) -> Result<T, ContainerError<ApiError>>`: builds the entry with `finish`, inserts it; on insert error logs `logger::error!` with only `operation` and `audit_id`, then returns `Err(ApiError::DatabaseInsertFailed("audit_log").into())`; otherwise returns `result` unchanged.
  - `pub fn emit_audit_event(operation: AuditOperation, tenant_id: &str, request_id: Option<&str>, success: bool)`: `logger::info!(target: "audit", ...)` with those fields only (D8).
  - Outcome rules in `finish`: `Ok` → `outcome = "success"`, `status_code = 200` (every audited handler returns `Json`, which axum sends as 200), `error_type = None`. `Err(e)` → `outcome = "failure"`, `status_code` = status of `(*e.error.current_context()).into_response()`, `error_type` = the `ApiError` variant name: the `Debug` text up to the first `(`, so `ValidationError("…")` becomes `ValidationError`.

- [ ] **Step 1: Write the failing tests** in `src/audit.rs`, with two in-test sinks: `MemorySink` (`std::sync::Mutex<Vec<AuditEntry>>`) and `FailingSink` (always `Err(StorageError::InsertError.into())`). Async tests use `#[tokio::test]`.
  - `record_writes_success_entry`: `record(&sink, PendingAudit::new("public", None, AuditOperation::LockerRetrieve).merchant("m1").customer("c1").resource("r1"), Ok::<_, ContainerError<ApiError>>(7))` returns `Ok(7)`; the sink holds one entry with `operation == "locker_retrieve"`, `outcome == "success"`, `status_code == 200`, `error_type == None`, `merchant_id == Some("m1")`, `customer_id == Some("c1")`, `resource_id == Some("r1")`, `tenant_id == "public"`, and `created_at` between two `now()` calls taken before and after (D4).
  - `record_writes_failure_entry`: `Err(ApiError::NotFoundError.into())` is returned unchanged; the entry has `outcome == "failure"`, `status_code == 404`, `error_type == Some("NotFoundError")`.
  - `record_maps_validation_error_to_400`: `Err(ApiError::ValidationError("entity_id must not be empty").into())` gives `status_code == 400` and `error_type == Some("ValidationError")`; the message text is absent from the serialized entry.
  - `record_fails_closed_when_sink_fails`: with `FailingSink` and `Ok(7)`, the result is `Err`, its `current_context()` matches `ApiError::DatabaseInsertFailed("audit_log")`, and `into_response().status()` is 500.
  - `parse_request_id_rejects_non_uuid`: `parse_request_id(Some("4111111111111111")) == None`, `parse_request_id(None) == None`, and `uuid::Uuid::now_v7().to_string()` comes back `Some` and equal.
  - `pending_truncates_long_ids`: `merchant`, `customer` and `resource` given a 300-character id store its first 255 characters.
- [ ] **Step 2: Run** `cargo test -j 4 audit::`. Expected: compile failure (items missing).
- [ ] **Step 3: Implement** the Interfaces above in `src/audit.rs` and add `pub mod audit;` to `src/lib.rs`. The builder methods keep at most 255 characters (`chars().take(255)`). Every `ApiError` variant is a unit or tuple variant (read in `src/error.rs`), so cutting the `Debug` text at the first `(` always yields the bare variant name.
- [ ] **Step 4: Run** `cargo test -j 4 audit::`. Expected: 6 passed.
- [ ] **Step 5: Run** `cargo test -j 4`. Expected: exit 0, 24 passed (18 + 6).
